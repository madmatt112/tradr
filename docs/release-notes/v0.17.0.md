Tradr v0.17.0 is out. It fits on your phone now, imports tastytrade exports, and can ask for a second factor when you sign in.

Four features this release, plus a security pass. If you use app.tradr.cloud you already have it. Self-hosters can pull it whenever, but read the upgrade notes at the bottom first, because the web container is stricter about its config now.

Tradr works on a phone. Below 768px the sidebar folds into a menu, and the positions list, the position page, the fill dialog, dashboard widgets and the settings tabs all fit the screen. You can install it to your home screen from the browser too. It still needs a connection; the service worker is there to make it installable and doesn't keep a copy of your journal offline.

The CSV importer has a tastytrade preset. Export Activity › Transactions as CSV and drop it in. The importer now reads a file's headers and suggests the preset that matches, so you may not even have to pick one. Stock and option trades come in, with commissions and fees added together per fill. Cash rows get skipped and the preview says how many. Expirations and assignments don't import yet, so close those positions by hand.

Running Tradr yourself got easier to do properly. There are ready-made Caddy and Traefik overrides that put it behind HTTPS with a real certificate: set `TRADR_DOMAIN` (plus `ACME_EMAIL` for Traefik) and add the override to `COMPOSE_FILE`. The [TLS page](https://docs.tradr.cloud/self-hosting/tls-reverse-proxy/) walks through both. The web container has a `/healthz` check and waits for the API to be healthy before it starts. And if you run the advisor, `OPENAI_BASE_URL` and `ANTHROPIC_BASE_URL` point it at a local model server like Ollama or LM Studio.

The docs picked up new pages on external Postgres, optional integrations, the trade calculator and the dashboard. The demo account's sample trades moved forward 8 weeks so they look recent again.

## Security hardening

Two-factor sign-in is here, and it's optional. Turn it on in Settings → Account with any authenticator app; you get 10 backup codes for when your phone isn't around. After 10 failed sign-ins in 15 minutes an account locks for 15 minutes, and operators get `tradr unlock` and `tradr disable-2fa` for when someone is stuck.

The API and both ways of serving the web app now send a Content Security Policy and the usual security headers. CI also runs a dependency audit that fails on a known advisory.

## Upgrade notes

For most installs, pulling and restarting is enough. Two things changed:

- **The web container checks its config at startup.** It exits with code 1 if `API_BASE_URL` is set and its origin doesn't match `^https?://[A-Za-z0-9.-]+(:[0-9]+)?$`. A value with no scheme, an IPv6 literal or an underscore in the hostname all fail. It also exits 1 if `csp-policy.txt` is missing from the image, which only matters if you build your own. A blank `API_BASE_URL` (the default) is fine.
- **`SESSION_SECRET` is gone.** Nothing reads it anymore, so you can delete it from `.env`.

The new start order and the TLS overrides live in the compose files, so grab the current `docker-compose.yml` (and the override you want) along with the new images.
